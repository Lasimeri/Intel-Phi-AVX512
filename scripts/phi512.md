# phi512.sh

Run a program that needs AVX-512 on a host that has none.

```sh
scripts/phi512.sh ./my-avx512-program [args...]
scripts/phi512.sh --verbose ./my-avx512-program   # each region the card ran, its phases and times
scripts/phi512.sh --card 1 ./my-avx512-program    # another card
scripts/phi512.sh --emulate ./my-avx512-program   # the software emulator, no card
scripts/phi512.sh --check                         # does this host even need it?
```

The program is not modified, recompiled, or asked to cooperate. See
`host/crates/phi512/src/lib.md` for what happens and what it costs.

## The space in the path

`LD_PRELOAD` splits its value on spaces and colons, and there is no
quoting that changes that. This repository may be checked out at
`Intel Phi AVX-512`, which contains spaces (a `git clone` makes
`Intel-Phi-AVX512`, which does not), and then the obvious invocation fails
with confusing errors about `/home/you/Intel`, `Phi` and
`AVX-512/host/...` each not being a shared object.

The wrapper therefore preloads through a space-free symlink to this
checkout, `~/.cache/intel-phi-avx512` (`$XDG_CACHE_HOME` when set), which it creates when missing and
re-points when it names another checkout (a second clone run after the
first). If the resolved path still contains a space it says so plainly
rather than letting the loader produce that error.

## Which build it picks

`PHI512_LIB`, when set, names the library outright. Otherwise, run from a
checkout: release if it exists, debug otherwise; the installed copy uses
`/usr/lib/libphi512.so`. The difference between the builds was large in
the emulator, because almost all of its work is decoding: 2101 ns per
instruction in release against 4382 ns in debug, measured 2026-09-21.

## Where the instructions execute (2026-09-22)

By default they execute on a Xeon Phi card: the wrapper's library
finds card 0's window (`PHI512_CARD=N` for another), checks that a
worker is polling it (`phi -c N vpu start`), and from then on every
AVX-512 instruction the program reaches is carried, with the code
around it, to the card's vector units (`host/crates/phi512/src/
offload.md`, `card/vpu/vpu_exec.md`). `--verbose` reports each region:
its bounds, how many chunks of the program's memory the card fetched
and wrote back, and the times. Without a card the first AVX-512
instruction stops the program with the reason; `PHI512_EMULATE=1` runs
the software emulator instead, which is the fallback and nothing more.

## Options (2026-09-22 evening)

`--card N` picks the card (else `PHI512_CARD`, else 0); `--emulate` runs
the AVX-512 in software instead (`PHI512_EMULATE`). The wrapper checks
that the card's worker is alive (the driver's `status`, which clears the
readiness word and waits for a live worker to re-assert it) and starts
it if not, deploying it first when the card has none; a worker start
turns unused swap on the window off itself. So the whole of it, from a
freshly booted card, is `scripts/phi512.sh ./program`. The worker start
reads `/dev/null`, not the wrapper's stdin, which is the program's: its
ssh read it before (measured 2026-09-25, Intel-Phi-Jev's `xks --site
avx512 query < req.json` found stdin empty when card 0 had no worker).

`--verbose` prints, per region, one line per phase: prologue, loop,
epilogue (or the whole region), the mode it ran in (`ranges`, `split on
N threads`, `demand`, or demand after the planner missed an address),
how many ranges, chunks, pages back and faults, and the fetch, run and
write-back times against the card's total and the wall time.

## Installed

Run from a checkout, the script's own `scripts/` is the checkout's and the
build tree's library is preferred. The copy `phi512-install.sh` puts in
`/usr/local/bin` has no checkout beside it: it carries the one it was
installed from (`installed_root`, or `PHI512_ROOT`) for the worker script
and driver, and preloads the installed `/usr/lib/libphi512.so`.
